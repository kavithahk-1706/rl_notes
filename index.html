Q1. Explain Value Iteration with suitable examples and applications.

Value Iteration is a planning algorithm used when we have a complete model of the environment — meaning we know exactly what happens after every action. Given that model, the goal is to figure out the best possible long-term value for every state, and from there, derive the best policy.

The Bellman Optimality Equation

The optimal value \(V^*(s)\) of any state satisfies this recursive relationship:

\[ V^*(s) = \max_a \left[ R(s,a) + \gamma \sum_{s'} P(s' \mid s, a)\, V^*(s') \right] \]
Reading this in plain English: the true value of a state is the reward you get from the best action, plus the discounted value of wherever that action takes you — weighted by how likely each landing state is. The \(\max_a\) means we always pick the action that gives us the most. \(\gamma\) (gamma, between 0 and 1) is the discount factor — it controls how much we care about future rewards. If \(\gamma\) is close to 1, we're very patient and plan far ahead. If it's close to 0, we're greedy and only care about the immediate reward.

How the Algorithm Works

The idea is simple: we don't know \(V^*\) ahead of time, so we start with a guess (usually all zeros) and keep applying the Bellman equation until our estimates stop changing. Here's the full process:

Step 1 — Initialize: Set \(V(s) = 0\) for every state \(s\). This is our starting guess.

Step 2 — Sweep: For every state, compute a new value using the current estimates of all neighbouring states:

\[ V_{\text{new}}(s) \leftarrow \max_a \left[ R(s,a) + \gamma \sum_{s'} P(s' \mid s,a)\, V(s') \right] \]

Step 3 — Check convergence: Compute \(\Delta = \max_s |V_{\text{new}}(s) - V(s)|\). If \(\Delta \lt \theta\) (some tiny threshold like 0.001), stop. Otherwise, set \(V \leftarrow V_{\text{new}}\) and repeat.

Step 4 — Extract policy: Once values have converged, the optimal action at any state is simply whichever action gives the highest Bellman value:

\[ \pi^*(s) = \arg\max_a \left[ R(s,a) + \gamma \sum_{s'} P(s'|s,a)\,V^*(s') \right] \]
This says: look at every possible action from state \(s\), compute the value of taking it (immediate reward + discounted future), and pick the action with the highest total. The policy is derived from the values — we don't learn it directly.

Grid World Example

Consider a 4×4 grid. The top-right cell is the goal (+1 reward), the bottom-left cell is a pit (−1 reward), and every other move costs −0.01. With \(\gamma = 0.9\), we start with all zeros. After several sweeps, values propagate outward from the goal:

Values start at zero and propagate outward from the +1 goal. States near the goal get higher values; states near the pit get penalized. γ = 0.9.

Notice that the bottom-left cell stays at −1 (it's a terminal pit), and the top-right stays at +1 (terminal goal). Every other cell's value reflects how reachable the goal is from there, discounted by how many steps it takes.

Convergence

Value Iteration is guaranteed to converge because the Bellman operator is a contraction mapping. This is a mathematical property that means every time you apply the update, the values move strictly closer to the true \(V^*\). The convergence rate depends on \(\gamma\) — smaller gamma means faster convergence because future rewards shrink quickly.

Important Properties

Value Iteration is a model-based method — it requires knowing the transition probabilities \(P(s'|s,a)\) and rewards \(R(s,a)\) upfront. This makes it impractical for real environments where we don't have a perfect model. It's also computationally expensive for large state spaces since it sweeps over every state at every iteration. For continuous state spaces, it's not directly applicable. These limitations are exactly what motivate the model-free methods like TD learning in Q2.

Applications

Value Iteration is used in robot navigation when a map is known (the robot knows where walls are and what moves are possible), in inventory management and scheduling problems where the system dynamics are known, and in game-playing when the full game tree is tractable (like chess endgame tablebases). It's also the theoretical foundation that most other RL algorithms build on.

Q2. Explain TD(0) — Temporal Difference Learning with 0-step lookahead.

TD(0) is a model-free method that learns value functions directly from experience, without needing to know transition probabilities or rewards in advance. The core insight is that you don't have to wait until the end of an episode to learn — you can update your estimate after every single step, using the next state's estimated value as a stand-in for the true future return.

The TD(0) Update Rule

\[ V(s_t) \leftarrow V(s_t) + \alpha \underbrace{\bigl[ r_{t+1} + \gamma\, V(s_{t+1}) - V(s_t) \bigr]}_{\text{TD error } \delta_t} \]
Breaking this down: \(V(s_t)\) is our current estimate of how good state \(s_t\) is. After taking a step, we receive reward \(r_{t+1}\) and land in \(s_{t+1}\). Our new estimate of \(s_t\)'s value is \(r_{t+1} + \gamma V(s_{t+1})\) — the actual reward we got, plus the discounted value of where we ended up. The difference between this new estimate and our old one is the TD error \(\delta_t\), which measures how surprised we were. We move our estimate a small step \(\alpha\) in the direction of that surprise.

The Backup Diagram

TD(0) takes one step, observes the reward, then uses V(s_{t+1}) as a proxy for the rest of the future.

The key phrase here is bootstrapping — we're using our own estimate of the next state's value to update our estimate of the current state. We're not waiting for the true return; we're using one estimate to improve another.

A Worked Example

Say you're in state \(s\) with current estimate \(V(s) = 5\). You take an action, receive reward \(r = 2\), and land in state \(s'\) with \(V(s') = 4\). With \(\gamma = 0.9\) and \(\alpha = 0.1\):

\[\delta = 2 + 0.9 \times 4 - 5 = 2 + 3.6 - 5 = 0.6\] \[V(s) \leftarrow 5 + 0.1 \times 0.6 = 5.06\]

The TD error was +0.6 (we did slightly better than expected), so we nudge \(V(s)\) upward a little. If the TD error were negative, we'd nudge it downward.

TD vs Monte Carlo vs Dynamic Programming

Dynamic Programming (Value Iteration) uses the full model — it knows \(P(s'|s,a)\) and computes expected values exactly. No trial-and-error experience needed, but you need the model.

Monte Carlo methods run a full episode to completion, then update using the actual total return \(G_t = r_{t+1} + \gamma r_{t+2} + \cdots\). This is unbiased (uses real data, not estimates), but it's slow because you can't learn until the episode ends, and variance is high because the return depends on many random steps.

TD(0) splits the difference. It learns online after every step (like MC wants to) but bootstraps off its own value estimates (like DP does). It's slightly biased — because \(V(s_{t+1})\) is an estimate, not the truth — but variance is much lower, and it works in continuing tasks with no natural episode end.

Convergence

TD(0) converges to the true \(V^\pi\) (the value function for the current policy \(\pi\)) under standard conditions: the learning rate \(\alpha\) must decrease over time following the Robbins-Monro conditions (\(\sum \alpha_t = \infty\), \(\sum \alpha_t^2 \lt \infty\)), and every state must be visited infinitely often. In practice with a fixed small \(\alpha\), it converges to a neighbourhood of \(V^\pi\).

Applications

TD(0) is used in game-playing (TD-Gammon famously used TD learning to master backgammon), real-time robot control, and anywhere you need online learning without a simulator. It's also the backbone of SARSA and Q-learning, which extend TD to control (learning policies, not just values).

Q3. Explain n-step TD Prediction with suitable examples and practical applications.

TD(0) only looks one step ahead before bootstrapping. Monte Carlo looks all the way to the end. n-step TD is the bridge — look \(n\) steps ahead, collect the actual rewards along the way, then bootstrap off the estimated value at the \(n\)-th state. The idea is that more steps means you're relying on real rewards rather than estimates, which reduces bias — but at the cost of higher variance because more random events are involved.

The n-step Return

After taking \(n\) steps from state \(s_t\), we collect rewards \(r_{t+1}, r_{t+2}, \ldots, r_{t+n}\) and end up in state \(s_{t+n}\). The n-step return is:

\[ G_t^{(n)} = r_{t+1} + \gamma r_{t+2} + \gamma^2 r_{t+3} + \cdots + \gamma^{n-1} r_{t+n} + \gamma^n V(s_{t+n}) \]
Each reward is discounted by one more power of \(\gamma\) because it's one step further in the future. The final term \(\gamma^n V(s_{t+n})\) is the bootstrap — we stop collecting real rewards there and use our current estimate of the value of the landing state. The update is then just like TD(0): \(V(s_t) \leftarrow V(s_t) + \alpha [G_t^{(n)} - V(s_t)]\).

The Bias-Variance Spectrum

n=1 is TD(0); n=∞ is Monte Carlo. n-step TD lets you tune where on this spectrum you sit.

The sweet spot for \(n\) is problem-dependent. If rewards are sparse and delayed (a robot only gets feedback after completing a task), larger \(n\) helps because you capture more of the actual reward signal before bootstrapping. If the environment is noisy and stochastic, smaller \(n\) is safer because longer sequences amplify variance.

Example: n = 3

Starting from state \(s_0\), we collect rewards \(r_1 = 2,\; r_2 = 1,\; r_3 = 3\) over three steps and land in \(s_3\) with \(V(s_3) = 5\). With \(\gamma = 0.9\):

\[ G_0^{(3)} = 2 + 0.9(1) + 0.81(3) + 0.729(5) = 2 + 0.9 + 2.43 + 3.645 = 8.975 \]

If \(V(s_0)\) was currently 7, the update would be \(V(s_0) \leftarrow 7 + \alpha(8.975 - 7)\), nudging it upward because the actual 3-step return was better than expected.

Relationship to TD(λ)

One practical problem with n-step TD is that you have to choose a single \(n\). TD(λ) (used in Q4) elegantly avoids this by computing a weighted average of all n-step returns simultaneously, controlled by the parameter \(\lambda\). It's the natural generalization of n-step TD.

Practical Applications

n-step TD is used in environments where single-step feedback is too myopic — game playing like Go and Chess where important feedback comes several moves after an action, robotic locomotion tasks where a stumble happens a few steps after the wrong foot placement, and multi-step dialogue systems where a response only shows its quality after a few conversational turns. It's also the theoretical building block for understanding eligibility traces and TD(λ).

Q4. Explain SARSA(λ), Watkins' Q(λ), and True Online TD(λ).

Instead of choosing one value of \(n\) for n-step TD, eligibility traces let you assign credit to all recently visited states simultaneously. Think of it like this: when a reward arrives, you don't just credit the state you're in right now — you credit every state you've been in recently, with the credit fading the further back you go. The eligibility trace \(e(s)\) is the bookkeeping mechanism for this.

Eligibility Traces

\[ e_t(s) = \begin{cases} \gamma\lambda\, e_{t-1}(s) + 1 & \text{if } s = s_t \\ \gamma\lambda\, e_{t-1}(s) & \text{otherwise} \end{cases} \]
When you visit a state, its trace jumps up by 1. For all states (visited or not), the trace decays by \(\gamma\lambda\) every timestep. So recently visited states have high traces; states visited long ago have traces near zero. When a reward comes, each state's value is updated proportionally to its trace — recent states get more credit.
When a reward arrives at t=4+, credit flows backward. States visited recently (high trace) get more credit than older ones.

SARSA(λ) — On-policy Control

SARSA(λ) extends standard SARSA (which learns Q-values for state-action pairs using the current policy) with eligibility traces. At each timestep, you compute the TD error \(\delta = r + \gamma Q(s',a') - Q(s,a)\) as usual. But instead of only updating \(Q(s,a)\), you update every state-action pair proportionally to its trace:

\[ Q(s,a) \leftarrow Q(s,a) + \alpha\,\delta\,e(s,a) \quad \text{for all } (s,a) \]

The trace \(e(s,a)\) is then decayed: \(e \leftarrow \gamma\lambda\, e\). Because the next action \(a'\) comes from the current policy (on-policy), SARSA(λ) is safe to use with exploration — it converges even when the agent is exploring.

Watkins' Q(λ) — Off-policy Control

Q(λ) is the off-policy version — it tries to learn the optimal Q-function regardless of the exploration policy. The critical difference: whenever the agent takes a non-greedy (exploratory) action, the eligibility trace is cut to zero:

\[ e_t(s,a) = \begin{cases} \gamma\lambda\, e_{t-1}(s,a) + 1 & \text{if } (s,a) = (s_t, a_t) \text{ and } a_t \text{ is greedy} \\ 0 & \text{if } a_t \text{ is non-greedy (exploration)} \end{cases} \]
The reasoning: if you took an exploratory action, that experience doesn't belong to the optimal policy you're trying to learn. Crediting earlier states through an exploratory transition would be misleading — the trajectory you followed wasn't what the greedy policy would have done. So you wipe the slate clean. This makes Q(λ) off-policy, but it also means exploration reduces the effective lookback, hurting sample efficiency.

True Online TD(λ)

Standard online TD(λ) accumulates traces in a way that slightly diverges from the theoretically ideal (offline) TD(λ). True Online TD(λ) corrects this by using dutch traces:

\[ e_t = \gamma\lambda\, e_{t-1} + \bigl(1 - \alpha\gamma\lambda\, e_{t-1}^\top x_t\bigr)\, x_t \]
The correction term \((1 - \alpha\gamma\lambda\, e_{t-1}^\top x_t)\) prevents a state from getting double-counted if it's visited multiple times in quick succession. With accumulating traces, revisiting a state quickly inflates its trace too much; dutch traces compensate. The result is that True Online TD(λ) exactly matches the offline TD(λ) solution — it's theoretically the cleanest version.

In summary: SARSA(λ) is the practical on-policy workhorse. Watkins' Q(λ) extends Q-learning to traces but at the cost of cutting them on exploration. True Online TD(λ) is the theoretically correct version, preferred when using linear function approximation where you need precise updates.

Q5. Discuss Neural Networks, Tile Coding, and RBFs as function approximators in RL.

Once state spaces become large or continuous — a robot's joint angles, pixel inputs, sensor readings — we can't store a value for every single state in a table. Instead, we parameterize the value function as \(\hat{V}(s,\mathbf{w})\), where \(\mathbf{w}\) is a set of learnable weights. The learning algorithm then adjusts \(\mathbf{w}\) rather than individual table entries. The key question is: what form does \(\hat{V}\) take?

The General Update

Regardless of the approximator, the weight update follows stochastic gradient descent on the TD error:

\[ \mathbf{w} \leftarrow \mathbf{w} + \alpha\,\delta_t\,\nabla_{\mathbf{w}}\,\hat{V}(s_t, \mathbf{w}) \]
\(\delta_t\) is the TD error (the surprise). \(\nabla_{\mathbf{w}}\hat{V}\) is the gradient — it points in the direction of increasing \(\hat{V}\) with respect to the weights. We move the weights in that direction by a fraction \(\alpha\) scaled by the TD error. What differs between the three methods below is what \(\nabla_{\mathbf{w}}\hat{V}\) looks like.

1. Tile Coding

Tile coding divides the state space into multiple overlapping grids called tilings. Each tiling is offset from the others slightly. For any state \(s\), exactly one tile per tiling is "active" — the tile that \(s\) falls into. The feature vector \(\phi(s)\) is binary: 1 for each active tile, 0 for all others.

State s activates one tile in each tiling. Multiple offset tilings give fine-grained, smooth coverage.

Because the value function is linear in the weights, \(\nabla_{\mathbf{w}}\hat{V} = \phi(s)\), and the update just increments the weights for active tiles. The overlapping tilings give smooth generalization — nearby states share many active tiles and therefore have similar estimated values. Tile coding is fast, interpretable, and works well for low-dimensional continuous spaces (like the Mountain Car or CartPole problems).

2. Radial Basis Functions (RBFs)

RBFs place Gaussian "bumps" at chosen centers \(c_i\) across the state space. Each feature measures how close state \(s\) is to center \(c_i\):

\[ \phi_i(s) = \exp\!\left(-\frac{\|s - c_i\|^2}{2\sigma_i^2}\right), \qquad \hat{V}(s,\mathbf{w}) = \sum_i w_i\,\phi_i(s) \]
\(\|s - c_i\|^2\) is the squared distance from state \(s\) to center \(c_i\). The exponential makes features decay smoothly with distance — states near the center get a value close to 1, states far away get values near 0. \(\sigma_i\) controls the width of the bump: larger \(\sigma\) = more generous generalization across distance. Unlike tile coding's binary features, RBF features are continuous and smooth.

RBFs give smooth, continuous generalization and are well-suited for environments with continuous dynamics. The downside is that center placement and \(\sigma\) values need to be chosen carefully, and it doesn't scale well to very high-dimensional spaces.

3. Neural Networks

A neural network directly maps the state \(s\) to \(\hat{V}(s,\mathbf{w})\) through multiple layers of learned transformations. The weights \(\mathbf{w}\) are all the parameters of the network — potentially millions of them. The gradient \(\nabla_{\mathbf{w}}\hat{V}\) is computed via backpropagation, and the weights update via the same TD gradient descent formula.

Neural networks can learn arbitrarily complex, non-linear value functions from raw inputs like pixels. This is what makes DQN possible — the Q-network takes raw Atari frames as input. However, combining neural networks with RL introduces instabilities (covered in Q7, Q8, Q9) that tile coding and RBFs avoid because they're linear and better understood theoretically.

Q6. Explain LSTD and LSPI with suitable examples and applications.

Standard TD learning updates weights incrementally, one sample at a time, using gradient descent. LSTD takes a completely different approach: collect a batch of samples, then solve directly for the optimal weights in one shot using linear algebra. No learning rate, no iterations — just a matrix equation.

Setting: Linear Value Function

We assume \(\hat{V}(s,\mathbf{w}) = \mathbf{w}^\top \phi(s)\), where \(\phi(s)\) is a feature vector. We want to find the weights \(\mathbf{w}\) such that the TD fixed-point condition holds across all samples.

LSTD — Least-Squares Temporal Difference

From a dataset of transitions \((s_t, r_t, s_{t+1})\), we accumulate two quantities:

\[ A = \sum_t \phi(s_t)\bigl[\phi(s_t) - \gamma\,\phi(s_{t+1})\bigr]^\top \]
\[ \mathbf{b} = \sum_t \phi(s_t)\,r_t \]
\(A\) captures how the feature vector at the current state relates to the discounted feature vector at the next state — it encodes the TD structure of the problem. \(\mathbf{b}\) accumulates the immediate rewards weighted by features. Together they form the linear system \(A\mathbf{w} = \mathbf{b}\), whose solution \(\mathbf{w}^* = A^{-1}\mathbf{b}\) is the set of weights that best satisfies the TD equations across all samples at once.

The entire dataset is used in one matrix inversion. No learning rate to tune, no convergence to wait for across many passes. This makes LSTD much more sample efficient than incremental TD — every data point is fully exploited.

The main limitation is computational: the matrix \(A\) is \(d \times d\) where \(d\) is the number of features. Inverting it costs \(O(d^3)\), so LSTD becomes expensive with thousands of features. For small to medium feature sets (up to a few hundred), it's excellent.

LSPI — Least-Squares Policy Iteration

LSTD evaluates a given policy (computes its Q-function). LSPI wraps LSTD in the classic policy iteration loop to find the optimal policy:

LSPI alternates: LSTD evaluates the current policy, then the greedy step improves it.

Crucially, LSPI can work off-policy — the collected dataset doesn't need to come from the policy being evaluated. You collect samples once (using any policy, even random exploration), and LSPI uses that same fixed dataset for all iterations of policy improvement. This is extremely valuable in settings where collecting data is expensive.

Applications

LSPI has been used in medical treatment optimization (where data is scarce and limited by clinical trial constraints), helicopter autopilot control (Ng et al., 2006 — LSPI trained on a small number of real flight samples), and financial portfolio management. Anywhere you have a limited dataset and can't afford online trial-and-error, the sample efficiency of LSTD/LSPI makes a strong case for using it.

Q7. Analyze Batch RL convergence — its principles, challenges, and practical applications.

Batch RL (also called offline RL) decouples data collection from learning. Instead of updating the value function after every step like online TD, you collect a fixed dataset of transitions first, then train on that dataset repeatedly — more like how supervised learning works than how online RL works.

Core Principle: Fitted Value Iteration (FVI)

The most general batch RL algorithm is Fitted Value Iteration. Given a fixed dataset \(\mathcal{D} = \{(s, a, r, s')\}\):

  1. Compute target values using the current Q-function: \(y_i = r_i + \gamma \max_{a'} Q(s_i', a')\)
  2. Treat \((s_i, a_i) \to y_i\) as a supervised regression problem and train a new Q-function on it
  3. Replace the old Q-function with the new one and repeat from step 1

The key phrase is "fixed dataset" — you never collect new data between iterations. You just reuse the same \(\mathcal{D}\) with increasingly refined targets.

FVI loops over the fixed dataset with better and better targets each time.

When Does It Converge?

With tabular representations, FVI is identical to value iteration and provably converges. With linear function approximation and on-policy data, it also converges — LSPI (Q6) is a special case of batch RL with proved convergence guarantees. The theory is solid in these cases because the function class is well-behaved.

The Deadly Triad — When It Breaks

Convergence breaks down when you simultaneously use all three of: function approximation (especially neural networks), bootstrapping (using Q estimates to compute targets), and off-policy data (data from a different policy than the one being learned). This combination is called the deadly triad, and it can cause Q-values to diverge or oscillate wildly.

The intuition: neural function approximation generalizes — updating one state's Q-value can inadvertently change the Q-values for many other states. Bootstrapped targets are themselves moving (because Q is being updated). And off-policy data means the distribution of states you're training on doesn't match the distribution your policy would actually visit. These three effects compound and can send Q-values to infinity.

Practical neural FVI (like Neural Fitted Q-Iteration, or batch variants of DQN) mitigates this with careful regularization, conservative target updates, and techniques like CQL (Conservative Q-Learning) that penalize overestimation of out-of-distribution actions.

Practical Applications

Batch RL is essential wherever you cannot safely run a learning agent online. In healthcare, you can't experiment on patients — but you can learn policies from historical electronic health records. In autonomous driving, you learn from logged human driving data before deploying the system on real roads. In industrial control, you learn from historical sensor data without risking equipment damage during exploration. The ability to learn from a fixed historical dataset, without any interaction with the live system, is what makes Batch RL uniquely valuable in safety-critical domains.

Q8. Explain Experience Replay and Fixed Target Networks.

When you try to train a neural network with basic Q-learning, two specific problems make it catastrophically unstable. Experience replay and fixed target networks are the two surgical fixes that address each problem independently. Together, they are what made DQN work.

Problem 1: Correlated Training Samples

Online Q-learning trains on transitions in the order they occur: \((s_1,a_1,r_1,s_2)\), then \((s_2,a_2,r_2,s_3)\), and so on. These consecutive samples are highly correlated — they come from the same trajectory, the same environment region. Neural network training assumes approximately i.i.d. (independent, identically distributed) data. When samples are correlated, gradient descent overfits to the current region of experience and forgets earlier parts of the state space. The network oscillates rather than converges.

Fix: Experience Replay

Maintain a replay buffer \(\mathcal{D}\) — a circular buffer that stores the last \(N\) transitions (typically \(N = 10^6\)). At each training step, instead of learning from the most recent transition, sample a random mini-batch from \(\mathcal{D}\):

New transitions are pushed into the buffer. Training samples are drawn randomly — breaking correlation.

Random sampling from the buffer breaks the correlation. Each mini-batch is drawn from a wide spread of past experience, giving the network a balanced view of the state space. As a bonus, each transition can be reused many times, making the algorithm much more data-efficient.

Problem 2: Non-Stationary Targets

The Q-learning loss involves a target value: \(y = r + \gamma \max_{a'} Q(s', a';\,\theta)\). The problem is that \(\theta\) — the network weights we're trying to update — also appears inside the target. Every gradient step that improves \(Q(s,a;\theta)\) simultaneously changes \(y\), which is computed from the same \(\theta\). You're updating your estimate while the goalposts keep moving. This causes oscillation and divergence.

Fix: Fixed Target Network

Keep a second network — the target network with weights \(\theta^-\) — that is a frozen copy of the main network. Use \(\theta^-\) to compute targets:

\[ y = r + \gamma \max_{a'} Q(s', a';\, \theta^-) \]
The target now uses \(\theta^-\) (frozen), while gradients update only \(\theta\) (the main network). Since \(\theta^-\) is frozen for \(C\) steps (e.g., every 10,000 steps we copy \(\theta \to \theta^-\)), the targets are stable for those \(C\) steps. This gives the main network time to converge toward stable targets before they shift again.
θ⁻ is a lagged snapshot of θ. Stable targets for C steps prevent the feedback loop.

It's worth emphasizing that these two tricks address completely different problems — replay handles sample correlation, target networks handle non-stationary targets. You need both. Using only replay still gives moving targets; using only the target network still gives correlated samples. Together, they are the minimal set of changes that stabilize deep Q-learning.

Q9. Compare DQN, Double DQN, and Dueling DQN with examples and applications.

DQN was the breakthrough that showed deep RL could work at scale. Double DQN identified and fixed a specific bias in DQN's update rule. Dueling DQN restructured the network architecture to learn more efficiently. Each is a targeted improvement over the previous one — none is a full redesign.

DQN (Deep Q-Network, 2013–2015)

DQN combines Q-learning with a deep convolutional neural network, experience replay, and a target network (see Q8). The training loss is:

\[ \mathcal{L}(\theta) = \mathbb{E}\!\left[\left(r + \gamma \max_{a'} Q(s', a';\,\theta^-) - Q(s,a;\,\theta)\right)^2\right] \]
We want \(Q(s,a)\) to equal the TD target \(r + \gamma \max_{a'} Q(s',a';\theta^-)\). The loss is the squared difference between them. The target network \(\theta^-\) is frozen to stabilize training. Minimizing this loss over a replay buffer of experiences trains the network to predict Q-values correctly.

Known problem: The \(\max_{a'}\) operation uses the target network \(\theta^-\) to both select the best action (the argmax) and evaluate how good that action is (the Q-value at the argmax). When Q-values are noisy (especially early in training), the max of noisy estimates is systematically higher than the true max. This causes overestimation bias — DQN values are consistently too optimistic.

Double DQN (2015)

The fix is simple: use the main network to select the action, but the target network to evaluate it:

\[ y = r + \gamma\, Q\!\left(s',\; \arg\max_{a'} Q(s',a';\,\theta);\; \theta^-\right) \]
Read this in two parts: first, \(\arg\max_{a'} Q(s',a';\theta)\) — the main network picks which action looks best. Second, \(Q(s', \text{that action};\, \theta^-)\) — the target network evaluates how good that chosen action actually is. Because two separate networks are involved, the overestimation from taking the max of noisy values is reduced significantly. If the main network overestimates action \(a^*\), the target network is likely to give a more conservative estimate for it.

This is a one-line change from DQN. The architecture and everything else stays the same. In practice, Double DQN consistently outperforms DQN, especially in later training where overestimation in DQN accumulates and causes instability.

Dueling DQN (2016)

Dueling DQN keeps the same training objective as DQN/Double DQN but restructures the network to decompose Q into two components:

\[ Q(s,a;\,\theta) = V(s;\,\theta) + \left[A(s,a;\,\theta) - \frac{1}{|\mathcal{A}|}\sum_{a'} A(s,a';\,\theta)\right] \]
\(V(s)\) is the state value — how good is it to just be in state \(s\), regardless of which action you take. \(A(s,a)\) is the advantage — how much better is action \(a\) compared to the average action from \(s\). The Q-value is their sum. The mean subtraction \(-\frac{1}{|\mathcal{A}|}\sum A\) ensures identifiability: without it, you could add a constant to \(V\) and subtract it from all \(A\) values without changing Q, making V and A impossible to learn separately.
DQN: one Q-head. Dueling: V and A heads combined. Same loss function; better gradient flow.

The advantage of decomposing Q this way is that in many states, the value of being there matters far more than which specific action you take — especially in states where all actions are roughly equivalent (like driving straight on an empty road). The V head can learn the state's value from those transitions without the A head needing to differentiate between actions. This leads to faster, more robust learning, especially in environments with large action spaces.

Applications

All three variants were benchmarked on the Atari-57 game suite. Dueling + Double DQN achieved state-of-the-art at the time. These architectures are now the standard baseline for discrete-action deep RL tasks: game playing, robotic discrete control, and trading systems.

Q10. Discuss Actor-Critic, A2C, and A3C with suitable examples and practical applications.

Value-based methods (DQN) learn Q-functions and derive policies implicitly from them. Policy gradient methods optimize the policy directly. Actor-Critic methods do both simultaneously: the actor is a policy network that chooses actions, and the critic is a value network that evaluates how good those actions were. The critic's feedback reduces the variance of the policy gradient update.

The Policy Gradient Problem

A pure policy gradient update is:

\[ \nabla_\theta J(\theta) = \mathbb{E}\!\left[\nabla_\theta \log \pi(a|s;\,\theta) \cdot G_t\right] \]

where \(G_t\) is the actual return from timestep \(t\). The problem is that \(G_t\) has very high variance — it's the sum of many random future rewards. This makes training slow and unstable. The fix is to replace \(G_t\) with the advantage \(A(s,a)\), which tells us not just how good the return was in absolute terms, but how much better it was than average:

\[ \nabla_\theta J(\theta) = \mathbb{E}\!\left[\nabla_\theta \log \pi(a|s;\,\theta) \cdot A(s_t,a_t)\right] \]
\(\nabla_\theta \log \pi(a|s;\theta)\) is the direction in parameter space that increases the probability of action \(a\) in state \(s\). We scale that direction by the advantage \(A(s_t,a_t)\). If the advantage is positive (the action was better than expected), we increase the probability of that action. If negative, we decrease it. The critic provides \(A(s,a) = r + \gamma V(s') - V(s)\) using its value estimates.

Actor-Critic Architecture

Actor selects actions; Critic computes advantage and trains Actor. Both learn simultaneously.

The critic is trained with standard TD: \(\mathcal{L}_w = (r + \gamma V(s';\mathbf{w}) - V(s;\mathbf{w}))^2\). The actor is trained with the policy gradient, using the critic's advantage estimate to scale the update. Both networks learn from the same stream of experience.

A2C — Advantage Actor-Critic (Synchronous)

A2C runs \(N\) parallel copies of the environment simultaneously. Each worker collects a rollout (a fixed number of steps), then all workers synchronize — the gradients from all \(N\) workers are averaged, and a single update is applied to the shared network. The synchronization ensures that all workers train on the same network version at all times. This makes training deterministic and reproducible, easier to debug, and well-suited for GPU-based batch computation.

A3C — Asynchronous Advantage Actor-Critic (2016)

A3C removes the synchronization barrier. Each of the \(N\) workers independently:

  1. Copies the current global weights to its local network
  2. Runs for a few steps and computes gradients locally using its own experience
  3. Pushes its gradients to the global network (which applies them immediately)
  4. Pulls the updated global weights and repeats

Workers don't wait for each other — they run asynchronously. This means the global network receives a constant stream of gradient updates from all workers. The asynchrony acts as a natural decorrelation mechanism — different workers are in different parts of the environment, so their gradients are diverse. No replay buffer is needed.

The trade-off is that A3C is non-deterministic (workers may apply stale gradients to an already-updated network) and harder to reproduce. On modern GPUs, A2C typically matches or exceeds A3C performance because vectorized environments allow efficient batched computation. A3C was designed for multi-CPU parallelism, which was the bottleneck at the time of its publication.

Applications

Actor-Critic methods are the backbone of modern deep RL. A3C was used to learn to play a range of Atari games and navigate 3D environments. The actor-critic framework underpins AlphaStar (StarCraft II), OpenAI Five (Dota 2), and the PPO and SAC algorithms widely used in continuous robotic control today.

Q11. Explain POMDPs, Belief States, and Belief State Updates with examples.

A standard MDP assumes the agent can observe the true state of the environment perfectly at every step. A POMDP relaxes this assumption — the agent only receives a partial, noisy observation of the true state. You can't see the full picture; you have to reason about what state you might be in, given everything you've seen so far.

POMDP Formal Definition

A POMDP extends an MDP with observations. It is defined by a 7-tuple \((\mathcal{S}, \mathcal{A}, \mathcal{O}, T, \Omega, R, \gamma)\):

  • \(\mathcal{S}\): the set of hidden states (the agent cannot directly observe these)
  • \(\mathcal{A}\): the set of actions
  • \(\mathcal{O}\): the set of observations (what the agent actually perceives)
  • \(T(s'|s,a)\): transition probability — how the hidden state evolves
  • \(\Omega(o|s',a)\): observation probability — how likely is observation \(o\) given you've transitioned to hidden state \(s'\) via action \(a\)
  • \(R(s,a)\): reward (depends on the hidden state)
  • \(\gamma\): discount factor

Belief States

Since the agent can't observe \(s\) directly, it maintains a belief state \(b\) — a probability distribution over all possible current hidden states. \(b(s) = P(\text{current state is } s \mid \text{all past observations and actions})\). This belief is a sufficient statistic for the full history — all the information you need to act optimally is encoded in \(b\). This means a POMDP over hidden states can be converted into an MDP over belief states.

Belief Update — Bayes Filter

After taking action \(a\) and receiving observation \(o\), the belief is updated using Bayes' theorem:

\[ b'(s') = \eta\; \Omega(o \mid s', a) \sum_{s \in \mathcal{S}} T(s' \mid s, a)\, b(s) \]
Breaking this down: \(\sum_s T(s'|s,a)\,b(s)\) is the predicted probability of being in state \(s'\) after taking action \(a\), averaging over all states we might have been in (weighted by our old belief \(b(s)\)). Then \(\Omega(o|s',a)\) multiplies this by how likely the observation \(o\) we actually received is, given we're now in \(s'\). States that are consistent with the observation get their probability boosted; states inconsistent with it get suppressed. Finally, \(\eta\) is a normalizing constant to make the distribution sum to 1.

Example: Tiger Problem

A tiger is behind one of two doors (Left or Right). You can't see which — you can only listen. Your prior belief: 50% tiger on Left, 50% on Right.

Hearing a growl from the left updates our belief: 85% tiger on left. We open the right door.

If you hear a growl from the Left side again, the belief updates further — maybe 97% tiger on the left now. If you hear one from the Right, the belief shifts back toward 50/50. The belief tracks everything you know.

Solving POMDPs

The exact solution to a POMDP is an MDP over the continuous belief-state space. This is solved with Point-Based Value Iteration (PBVI) — it samples a finite set of belief points and computes value functions over them. For large state spaces, this is intractable, so approximate methods are used: recurrent neural networks (like LSTMs) can implicitly maintain a belief state through their hidden state, enabling end-to-end learning in partially observable environments without explicitly computing the belief update.

Applications

POMDPs model robotic localization (GPS dropout, noisy sensors), medical diagnosis (lab results are noisy proxies for the true disease state), dialogue systems (the user's true intent is hidden — you only observe their words), and security tasks where you have incomplete information about the adversary's state.

Q12. Discuss Options Framework and MAXQ with suitable examples and applications.

Both Options and MAXQ are hierarchical RL approaches. The core motivation is that many real-world tasks have natural sub-task structure — "make coffee" decomposes into "go to kitchen," "fill kettle," "wait for boil," and so on. Instead of learning from raw primitive actions (each millisecond of movement), hierarchical methods let the agent operate at multiple levels of abstraction simultaneously.

Options Framework

An option is a temporally extended action — a sub-policy that runs for multiple timesteps until a termination condition is met. Formally, an option is a triple \(\omega = \langle I, \pi_\omega, \beta \rangle\):

  • \(I \subseteq \mathcal{S}\): the initiation set — the set of states from which this option can be started
  • \(\pi_\omega : \mathcal{S} \to \mathcal{A}\): the option policy — what primitive actions to take while executing this option
  • \(\beta : \mathcal{S} \to [0,1]\): the termination condition — the probability of stopping this option in each state

At the top level, the meta-policy picks an option to execute. The chosen option then runs its own policy, taking primitive actions, until it terminates according to \(\beta\). Then the meta-policy picks the next option. This turns the MDP into a Semi-MDP (SMDP) — actions happen over variable amounts of time.

Two-level hierarchy. Meta-policy picks options; each option runs until its termination condition β fires.

The key advantage of options is reusability. If "navigate to room A" is learned as an option, it can be called from any task that requires getting to room A, without re-learning navigation from scratch. Options can also be defined by hand (using domain knowledge) or discovered automatically through subgoal identification algorithms.

MAXQ Value Decomposition

MAXQ is a specific hierarchical decomposition method that defines a task graph — a hierarchy of tasks where each task can call sub-tasks. MAXQ decomposes the Q-function of any task \(i\) into two parts:

\[ Q(i, s, a) = V(a, s) + C(i, s, a) \]
\(V(a, s)\) is the value of completing sub-task \(a\) starting from state \(s\) — the total expected (discounted) reward that sub-task \(a\) earns on its own. \(C(i, s, a)\) is the "completion" value — the additional reward the parent task \(i\) expects to collect after sub-task \(a\) finishes. Together they sum to the full Q-value from task \(i\)'s perspective. This decomposition is recursive: \(V(a, s)\) can itself be decomposed into its own sub-tasks' Q-values.

Taxi Problem: MAXQ in Action

The classic demonstration of MAXQ is the Taxi problem: a taxi must navigate a grid, pick up a passenger from a specified source location, and drop them at a destination.

The MAXQ task hierarchy looks like this: the root task MaxTaxi calls two sub-tasks in sequence — Get (pick up the passenger) and Put (drop off the passenger). Get itself calls Navigate (move to the passenger's location) followed by Pickup. Put calls Navigate (to the destination) followed by Dropoff. The Navigate sub-task uses the four primitive movement actions.

Notice that Navigate is reused by both Get and Put. Once Navigate is learned, both sub-tasks benefit. This is transfer learning built into the architecture — sub-task policies are trained once and shared wherever that sub-task appears.

Options vs MAXQ

Options is a general framework — it specifies what a hierarchical action looks like (the triple \(\langle I, \pi, \beta \rangle\)) but doesn't prescribe how the value function should be structured. MAXQ is a specific algorithmic approach that decomposes the Q-function recursively, enabling independent learning of sub-tasks and explicit transfer. Options are more flexible; MAXQ provides stronger theoretical structure and better sample efficiency when the task hierarchy is known.

Applications

Hierarchical RL is used in robotic manipulation (reach → grasp → place), long-horizon navigation with subgoals, and Atari games with sparse rewards like Montezuma's Revenge where the agent must complete dozens of sub-tasks before any reward arrives. It's also being applied to multi-step reasoning in language models, where subtask decomposition mirrors chain-of-thought planning.
