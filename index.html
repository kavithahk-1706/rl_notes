Reinforcement Learning — Mid 2

Exam Prep · 12 Important Questions · Units 3, 4 & 5

Q1. Explain Value Iteration with suitable examples and applications.

Core idea: In a fully known environment (we know transitions and rewards), we want to find the best possible value for every state. Value Iteration repeatedly applies the Bellman optimality equation until values stop changing.

Bellman Optimality Equation

The optimal value \(V^*(s)\) of a state is the best reward you can get from it, considering all future steps:

\[ V^*(s) = \max_a \left[ R(s,a) + \gamma \sum_{s'} P(s' \mid s, a)\, V^*(s') \right] \]

Read it as: best action × (immediate reward + discounted future value).

Algorithm

  1. Initialize \(V(s) = 0\) for all states.
  2. For every state, apply the Bellman equation to update \(V(s)\).
  3. Repeat until the maximum change \(\Delta \lt \theta\) (some tiny threshold).
  4. Extract policy: \(\pi^*(s) = \arg\max_a \left[ R(s,a) + \gamma \sum_{s'} P(s'|s,a)\,V(s') \right]\).

Grid World Example

4×4 grid. Goal = top-right (+1), pit = bottom-left (−1), all moves cost −0.01. We start with all zeros and sweep until the values converge:

Grid world: values start at 0, converge toward the +1 goal (green) and away from the −1 pit (red). γ = 0.9.

Key Points to Remember

  • Requires a model — you must know \(P(s'|s,a)\) and \(R(s,a)\). This is dynamic programming, not trial-and-error RL.
  • Convergence guaranteed — the Bellman operator is a contraction; repeated application always converges.
  • \(\gamma\) (discount factor, 0–1) controls how much future reward matters. \(\gamma = 0\) = greedy, \(\gamma \to 1\) = long-sighted.
  • Policy extraction — once \(V^*\) is found, pick the greedy action at each state.

Applications

  • Robot path planning (known map)
  • Game solving (chess endgames with full state info)
  • Inventory management, scheduling

Q2. Explain TD(0) — Temporal Difference Learning with 0-step lookahead.

Core idea: TD(0) learns directly from experience — no model needed. It updates value estimates after every single step by comparing what it expected vs. what it actually got.

The Update Rule

\[ V(s_t) \leftarrow V(s_t) + \alpha \,\underbrace{\bigl[r_{t+1} + \gamma\, V(s_{t+1}) - V(s_t)\bigr]}_{\text{TD error } \delta_t} \]
  • \(\alpha\) = learning rate (how much we trust the new info)
  • \(r_{t+1} + \gamma V(s_{t+1})\) = TD target — what we now think the value is
  • \(\delta_t\) = TD error — the surprise; how wrong our old estimate was

Backup Diagram

TD(0) looks one step ahead and bootstraps off its own estimate of V(s').

TD vs Monte Carlo vs DP

  • DP: knows the model, updates using true \(P(s'|s,a)\). No experience needed.
  • Monte Carlo: waits until episode ends, then updates using the full real return \(G_t\). High variance, unbiased.
  • TD(0): updates after each step, bootstraps off \(V(s')\). Low variance, slightly biased — but works online.

Simple Walkthrough

Say \(V(s) = 5\), we take a step, get \(r = 2\), land in \(s'\) with \(V(s') = 4\), \(\gamma = 0.9\), \(\alpha = 0.1\):

\[\delta = 2 + 0.9 \times 4 - 5 = 2 + 3.6 - 5 = 0.6\] \[V(s) \leftarrow 5 + 0.1 \times 0.6 = 5.06\]

Key Points

  • Works in continuing (non-episodic) tasks — doesn't need episode end.
  • Online — updates every step, can react quickly to new experience.
  • The "0" in TD(0) means 0 additional lookahead steps beyond the immediate next state.
  • Converges to the maximum likelihood Markov model estimate of V.

Q3. Explain n-step TD Prediction with suitable examples and practical applications.

Core idea: TD(0) looks 1 step ahead. Monte Carlo looks all the way to the end. n-step TD is the middle ground — look n steps ahead, then bootstrap off the estimated value there.

n-step Return

\[ G_t^{(n)} = r_{t+1} + \gamma r_{t+2} + \cdots + \gamma^{n-1} r_{t+n} + \gamma^n V(s_{t+n}) \]

Then update:

\[ V(s_t) \leftarrow V(s_t) + \alpha \bigl[ G_t^{(n)} - V(s_t) \bigr] \]

The Spectrum

n=1 (TD) and n=∞ (MC) are the extremes. n-step TD lets you tune the trade-off.

Example: n=3

You're in state \(s_0\), take actions, collect rewards \(r_1 = 2,\, r_2 = 1,\, r_3 = 3\), and land in \(s_3\) with \(V(s_3) = 5\). With \(\gamma = 0.9\):

\[ G_0^{(3)} = 2 + 0.9 \times 1 + 0.81 \times 3 + 0.729 \times 5 = 2 + 0.9 + 2.43 + 3.645 = 8.975 \]

Practical Applications

  • Games: Backgammon, Go — n-step helps when rewards are delayed but episode end is very far away.
  • Robotics: locomotion tasks where a fall (bad reward) happens a few steps after the wrong action.
  • Basis for TD(λ) — eligibility traces blend all n-step returns simultaneously (see Q4).

Key Point

The best \(n\) is problem-dependent. In practice, \(\lambda\)-returns (TD(λ)) are preferred because they avoid picking a single n and instead average over all of them.

Q4. Explain SARSA(λ), Watkins' Q(λ), and True Online TD(λ).

Core idea: Eligibility traces are a memory of recently visited states/actions. When you get a reward, you credit not just the current state but all recently visited ones — fading the credit with recency.

Eligibility Trace

For each state (or state-action pair), maintain a trace \(e(s)\) that increases when you visit and decays over time:

\[ e_t(s) = \begin{cases} \gamma\lambda\, e_{t-1}(s) + 1 & \text{if } s = s_t \\ \gamma\lambda\, e_{t-1}(s) & \text{otherwise} \end{cases} \]

\(\lambda \in [0,1]\) controls how far back credit spreads. \(\lambda=0\) = TD(0), \(\lambda=1\) = MC.

When a reward arrives, eligibility traces distribute credit backward. Recent states get more.

SARSA(λ) — On-policy

Standard SARSA extended with eligibility traces. At each step:

  1. Compute TD error: \(\delta = r + \gamma Q(s', a') - Q(s,a)\)
  2. Update eligibility trace: \(e(s,a) \mathrel{+}= 1\)
  3. For all state-action pairs: \(Q(s,a) \leftarrow Q(s,a) + \alpha\delta\, e(s,a)\)
  4. Decay all traces: \(e(s,a) \leftarrow \gamma\lambda\, e(s,a)\)

Because it uses \((s,a,r,s',a')\) — the current policy's next action — it's on-policy.

Watkins' Q(λ) — Off-policy

Like Q-learning with traces. The key difference: if the agent takes a non-greedy (exploratory) action, the trace is cut to zero.

\[ e_t(s,a) = \begin{cases} \gamma\lambda\, e_{t-1}(s,a) + 1 & \text{greedy action at }s_t \\ 0 & \text{non-greedy (exploratory) action} \end{cases} \]

This makes it off-policy (learns about greedy policy even while exploring), but cutting traces on exploration reduces efficiency.

True Online TD(λ)

A corrected version of online TD(λ) that uses dutch traces instead of accumulating traces. It exactly matches the offline (batch) TD(λ) update — no approximation. It's the theoretically cleaner version.

\[ e_t = \gamma\lambda\, e_{t-1} + (1 - \alpha\gamma\lambda\, e_{t-1}^\top x_t)\, x_t \]

The correction term \((1 - \alpha\gamma\lambda\, e_{t-1}^\top x_t)\) prevents double-counting when the same state is visited multiple times.

Summary Table

  • SARSA(λ): on-policy, soft traces, practical and widely used
  • Watkins' Q(λ): off-policy, cuts trace on exploration — loses some efficiency
  • True Online TD(λ): theoretically exact, best for linear function approximation

Q5. Discuss Neural Networks, Tile Coding, and RBFs as function approximators in RL.

Core idea: In large state spaces (robot joints, pixels), we can't store a value for every state. Instead, we approximate \(V(s)\) using a parameterized function \(\hat{V}(s, \mathbf{w})\) and learn the weights \(\mathbf{w}\).

General Update (SGD)

\[ \mathbf{w} \leftarrow \mathbf{w} + \alpha\,\delta\,\nabla_{\mathbf{w}}\,\hat{V}(s, \mathbf{w}) \]

The gradient \(\nabla_{\mathbf{w}}\hat{V}\) is what differs between the three methods below.

1. Tile Coding

Divide the state space into multiple overlapping grids (tilings). Each state activates exactly one tile per tiling. The feature vector is binary — 1 for active tiles, 0 otherwise.

State s activates one tile per tiling. Multiple tilings give fine-grained coverage.

Advantage: Generalization is local and controllable. Fast to compute.

2. Radial Basis Functions (RBFs)

Place Gaussian bumps at centers \(c_i\) across the state space. Each feature measures how close state \(s\) is to center \(c_i\):

\[ \phi_i(s) = \exp\!\left(-\frac{\|s - c_i\|^2}{2\sigma_i^2}\right), \qquad \hat{V}(s,\mathbf{w}) = \sum_i w_i\,\phi_i(s) \]

\(\sigma_i\) controls how wide each bump is (how far the generalization reaches). Smooth, continuous generalization — good for continuous state spaces.

3. Neural Networks

Use a NN to directly output \(\hat{V}(s,\mathbf{w})\) or \(\hat{Q}(s,a,\mathbf{w})\). Update weights via gradient descent on the TD error:

\[ \mathbf{w} \leftarrow \mathbf{w} + \alpha\,\delta\,\nabla_{\mathbf{w}}\,\hat{Q}(s,a,\mathbf{w}) \]

The gradient is computed via backpropagation. NNs can learn complex non-linear value functions — essential for pixel-based inputs (DQN).

Comparison

  • Tile Coding: simple, fast, interpretable, works well for low-dim continuous spaces
  • RBF: smooth generalization, needs good center placement, still linear in weights
  • NN: most powerful, handles raw inputs, but needs stabilization tricks (see Q8/Q9)

Q6. Explain LSTD and LSPI with suitable examples and applications.

Core idea: Instead of gradient descent (slow, iterative), LSTD solves directly for the best weight vector \(\mathbf{w}\) in one shot using linear algebra. LSPI wraps LSTD in a policy iteration loop.

Setup: Linear Value Function

We assume \(\hat{V}(s, \mathbf{w}) = \mathbf{w}^\top \phi(s)\) — linear in features \(\phi(s)\).

LSTD — Least-Squares TD

We want \(\mathbf{w}\) such that the TD fixed-point holds. This means solving:

\[ A\,\mathbf{w} = \mathbf{b} \]

where, accumulated over samples \((s_t, r_t, s_{t+1})\):

\[ A = \sum_t \phi(s_t)\bigl[\phi(s_t) - \gamma\,\phi(s_{t+1})\bigr]^\top, \qquad \mathbf{b} = \sum_t \phi(s_t)\,r_t \]

Then \(\mathbf{w}^* = A^{-1}\mathbf{b}\). One matrix solve — no learning rate, no iterations needed.

Why LSTD > plain TD?

  • No learning rate to tune
  • More sample-efficient (uses all data at once)
  • Stable: guaranteed to converge for linear approximation

Downside: \(A\) is \(d \times d\) (d = feature size). Inverting it costs \(O(d^3)\) — not scalable to huge feature spaces.

LSPI — Least-Squares Policy Iteration

Full policy iteration using LSTD for evaluation:

  1. Policy Evaluation: run LSTD on samples from the current policy \(\pi\) to get \(\hat{Q}^\pi(s,a,\mathbf{w})\)
  2. Policy Improvement: \(\pi'(s) = \arg\max_a \hat{Q}^\pi(s,a,\mathbf{w})\)
  3. Repeat until policy stops changing
LSPI alternates between LSTD evaluation and greedy policy improvement.

Applications

  • Medical treatment policies (small dataset, need sample efficiency)
  • Helicopter autopilot (Ng et al.) — few real-world samples, LSPI trains efficiently
  • Finance: portfolio management with moderate feature sets

Q7. Analyze Batch RL convergence — its principles, challenges, and practical applications.

Core idea: Instead of updating from one sample at a time, Batch RL collects a dataset of experiences first, then trains on the full dataset repeatedly. Like supervised learning, but for RL.

Principle: Fitted Value Iteration (FVI)

  1. Collect dataset \(\mathcal{D} = \{(s, a, r, s')\}\) using any policy (even random).
  2. Compute targets: \(y = r + \gamma\max_{a'} Q(s', a')\) using current Q.
  3. Fit a regression model to predict \(y\) from \((s,a)\) — this is your new Q.
  4. Repeat from step 2 until convergence.
Batch RL loops over a fixed dataset, iteratively refining the Q function via regression.

Convergence — When it works

  • Linear function approximation: FVI with linear models converges (proved).
  • LSPI (from Q6) is a batch method — guaranteed convergence with linear FA.
  • Tabular case: always converges (equivalent to value iteration).

Convergence — Challenges (Deadly Triad)

When you combine all three: function approximation + bootstrapping + off-policy data, convergence breaks down:

  • Extrapolation error: Q values for unseen state-actions can blow up.
  • Distribution mismatch: data was collected under a different policy — the bootstrap targets may be badly off.
  • Neural FVI (NFQ, batch DQN): can diverge or oscillate without careful regularization.

Practical Applications

  • Healthcare: learn policies from patient records — you can't run live experiments.
  • Autonomous driving: offline learning from logged driving data before deployment.
  • Atari: Neural Fitted Q (NFQ) was an early batch approach to game playing.

Q8. Explain Experience Replay and Fixed Target Networks.

Core idea: These are two tricks that make training deep Q-networks (DQN) stable. Without them, the training diverges. Together, they tame the deadly trio of correlation, non-stationarity, and feedback loops.

Problem 1 — Correlated Samples

If you train on \((s_1, a_1, r_1, s_2), (s_2, a_2, r_2, s_3), \ldots\) in order, consecutive samples are highly correlated (you're still in the same room of Atari). Gradient descent expects i.i.d. samples — correlation breaks it.

Fix: Experience Replay

Store every transition \((s, a, r, s')\) in a circular replay buffer \(\mathcal{D}\) (typically 1M entries). At each training step, sample a random mini-batch from \(\mathcal{D}\):

Each training step samples a random mini-batch from the buffer — breaks correlation.

Benefits: data efficiency (each sample reused many times), decorrelation.

Problem 2 — Moving Targets

In DQN, the loss is \(\bigl[r + \gamma \max_{a'} Q(s', a'; \theta) - Q(s,a; \theta)\bigr]^2\). The target \(r + \gamma \max Q\) uses the same network \(\theta\) we're updating. So every gradient step changes both the prediction and the target simultaneously — like chasing a moving goalposts. Very unstable.

Fix: Fixed Target Network

Keep a second target network \(\theta^-\) that is a frozen copy of the main network:

\[ y = r + \gamma \max_{a'} Q(s', a';\, \theta^-) \]

Update \(\theta\) via gradient descent on \((y - Q(s,a;\theta))^2\), but freeze \(\theta^-\) for \(C\) steps (e.g. every 10,000 steps, copy \(\theta \to \theta^-\)).

Target network is a lagged copy. Targets are stable for C steps, preventing feedback loops.

Key Points

  • Both tricks are needed together — replay alone doesn't fix moving targets.
  • Replay buffer size and target update frequency C are important hyperparameters.
  • Together, they were the critical innovations that made DQN work on Atari.

Q9. Compare DQN, Double DQN, and Dueling DQN with examples and applications.

Core idea: DQN was the breakthrough. Double DQN fixes its optimism bias. Dueling DQN restructures the network to learn faster. Each is a surgical improvement to the one before.

DQN (Deep Q-Network)

Standard Q-learning with a neural network, experience replay, and a target network (see Q8). Loss:

\[ \mathcal{L} = \left(r + \gamma \max_{a'} Q(s', a';\,\theta^-) - Q(s,a;\,\theta)\right)^2 \]

Problem: \(\max_{a'} Q(s',a';\theta^-)\) uses the same network to both select the best action and evaluate how good it is. This causes overestimation — values get systematically inflated.

Double DQN

Separate action selection (main network \(\theta\)) from action evaluation (target network \(\theta^-\)):

\[ y = r + \gamma\, Q\!\left(s',\; \underbrace{\arg\max_{a'} Q(s',a';\,\theta)}_{\text{select with } \theta};\; \underbrace{\theta^-}_{\text{evaluate with } \theta^-}\right) \]

Same two networks, just used differently. Reduces overestimation significantly. One line of code change from DQN.

Dueling DQN

Splits the Q-value into two components inside the network architecture:

\[ Q(s,a;\,\theta) = V(s;\,\theta) + \left[A(s,a;\,\theta) - \frac{1}{|\mathcal{A}|}\sum_{a'} A(s,a';\,\theta)\right] \]
  • \(V(s)\) = state value — how good is being in state \(s\) at all
  • \(A(s,a)\) = advantage — how much better is action \(a\) vs. average

The mean subtraction is for identifiability (otherwise V and A can't be uniquely recovered from Q). This helps in states where the action doesn't matter much — V is learned without forcing A to be all zeros.

DQN: single Q-head. Dueling: two heads (V and A) combined. Same loss, better learning.

Summary

  • DQN: Q-learning + NN + replay + target net. Works on Atari. Overestimates Q.
  • Double DQN: decouple selection/evaluation. Less overestimation, better performance.
  • Dueling DQN: split into V+A. Learns state values even from actions that don't matter. Better in large action spaces.

Applications

All three: Atari games, robotic control, trading algorithms. Dueling works especially well in games where many actions have similar effects (navigation games with lots of forward movement).

Q10. Discuss Actor-Critic, A2C, and A3C with suitable examples and applications.

Core idea: Actor-Critic splits the agent into two parts — the actor picks actions, the critic evaluates them. The critic's feedback trains the actor. It's the bridge between value-based (DQN) and policy-gradient methods.

Actor-Critic

Actor: policy network \(\pi(a|s;\,\theta)\) — outputs a probability over actions.
Critic: value network \(V(s;\,\mathbf{w})\) — evaluates how good the current state is.

The advantage \(A(s,a) = r + \gamma V(s') - V(s)\) tells the actor: "was that action better or worse than average?" Then:

\[ \nabla_\theta J(\theta) = \mathbb{E}\left[\nabla_\theta \log \pi(a|s;\,\theta)\cdot A(s,a)\right] \]

If \(A \gt 0\) (action was better than expected): increase its probability. If \(A \lt 0\): decrease it.

Critic loss: \(\mathcal{L}_w = \bigl(r + \gamma V(s';\mathbf{w}) - V(s;\mathbf{w})\bigr)^2\) — standard TD.

Actor selects actions; Critic evaluates them and feeds advantage back to train Actor.

A2C — Advantage Actor-Critic (Synchronous)

Run N workers in parallel, each collecting experience from independent environment copies. Wait until all workers finish a rollout, then compute the advantage and update the shared network. Synchronous = deterministic, reproducible.

A3C — Asynchronous Advantage Actor-Critic

Workers don't wait for each other. Each worker:

  1. Copies the global network weights.
  2. Runs for a few steps, computes gradients locally.
  3. Asynchronously pushes gradients to the global network.
  4. Pulls updated weights and repeats.

The asynchrony itself acts as a decorrelation mechanism — no replay buffer needed. But it's non-deterministic and harder to reproduce.

A2C vs A3C

  • A2C is simpler, more stable, often matches A3C performance on GPU.
  • A3C was designed for CPU parallelism (many cheap cores). On modern GPUs, A2C is generally preferred.

Applications

  • Continuous control: MuJoCo locomotion (HalfCheetah, Ant)
  • Game playing: StarCraft II (AlphaStar uses actor-critic at its core)
  • Robotics: dexterous manipulation

Q11. Explain POMDPs, Belief States, and Belief State Updates with examples.

Core idea: A standard MDP assumes you can observe the true state \(s\) perfectly. A POMDP says: what if you can't? You only get noisy, partial observations. The fix is to maintain a belief — a probability distribution over states — and update it every step.

POMDP = MDP + Observations

A POMDP is defined by a 7-tuple: \((\mathcal{S}, \mathcal{A}, \mathcal{O}, T, \Omega, R, \gamma)\)

  • \(\mathcal{S}\): hidden states
  • \(\mathcal{A}\): actions
  • \(\mathcal{O}\): observations (what you actually see)
  • \(T(s'|s,a)\): transition probability
  • \(\Omega(o|s',a)\): observation probability — how likely is observation \(o\) given new state \(s'\)
  • \(R(s,a)\): reward (depends on true hidden state)

Belief State

Since we don't observe \(s\), we maintain a distribution \(b(s) = P(\text{current state is } s \mid \text{history})\). This belief is the agent's effective state — it's a sufficient statistic for all past observations.

Belief Update (Bayes Filter)

After taking action \(a\) and observing \(o\):

\[ b'(s') = \eta\; \Omega(o \mid s', a) \sum_{s} T(s' \mid s, a)\, b(s) \]
  • \(\eta\) = normalizing constant (so \(b'\) sums to 1)
  • \(\sum_s T(s'|s,a)\,b(s)\) = predicted distribution over \(s'\) after taking \(a\)
  • \(\Omega(o|s',a)\) = likelihood of observation given we're actually in \(s'\)

Read it as: predicted belief × observation likelihood → updated belief.

Example: Tiger Problem

Tiger is behind one of two doors (Left or Right). You hear a growl to the Left.

Belief updates after observing a growl on the left — tiger probably on left, so open the right door.

Solving POMDPs

  • Exact: PBVI (Point-Based Value Iteration) — works on belief-space MDPs. Exponential in state size.
  • Approximate: Use belief as input to a neural network (deep RL); LSTM agents can implicitly maintain belief.

Applications

  • Robotic localization (GPS dropout zones)
  • Medical diagnosis (test results are noisy observations of the true disease state)
  • Dialogue systems (hidden user intent)

Q12. Discuss Options Framework and MAXQ with examples and practical applications.

Core idea: Both are hierarchical RL — break a long task into reusable sub-tasks. Instead of choosing a primitive action every millisecond, the agent can commit to a high-level option ("go to the kitchen") that runs for many steps.

Options Framework

An option \(\langle I, \pi, \beta \rangle\) is a temporally extended action:

  • \(I \subseteq \mathcal{S}\): initiation set — states where this option can start
  • \(\pi: \mathcal{S} \to \mathcal{A}\): option policy — what to do while executing this option
  • \(\beta: \mathcal{S} \to [0,1]\): termination condition — probability of stopping in each state

Options turn MDPs into SMDPs (Semi-MDPs) — actions take variable time. The top-level policy picks options; options internally execute primitive actions.

Two-level hierarchy: top picks options; each option runs its own internal policy to completion.

MAXQ Value Decomposition

MAXQ is a specific hierarchical decomposition where each task \(i\) in the hierarchy has its Q-value split into:

\[ Q(i, s, a) = V(a, s) + C(i, s, a) \]
  • \(V(a, s)\): the value of completing sub-task \(a\) starting from \(s\) (intrinsic value of the subtask)
  • \(C(i, s, a)\): the "completion" value — additional reward after sub-task \(a\) finishes, from the perspective of parent task \(i\)

This decomposition is recursive: each sub-task may itself contain further sub-tasks.

Example: Taxi Problem

The taxi must pick up a passenger and drop them off. MAXQ hierarchy:

  • Root: MaxTaxi → calls Get (pickup) then Put (dropoff)
  • Get: navigate to passenger → Pickup
  • Put: navigate to destination → Dropoff
  • Navigate: primitive moves (N/S/E/W)

Each sub-task is learned independently. The "Navigate" policy is reused by both Get and Put — transfer learning for free.

Options vs MAXQ

  • Options: general framework, options can be learned or hand-crafted, flexible termination
  • MAXQ: specific decomposition technique, recursive Q-decomposition, cleaner theoretical properties

Applications

  • Robot manipulation: reach → grasp → place (three options, each reusable)
  • Navigation with subgoals: room-by-room navigation
  • Game playing: Montezuma's Revenge (sparse reward; options help bridge gaps)
