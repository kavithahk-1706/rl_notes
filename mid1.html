Q1. Compare Reinforcement Learning, Supervised Learning, and Unsupervised Learning with suitable examples. 5M

The Three Paradigms

Machine Learning is broadly split into three paradigms based on what kind of feedback the learner gets. Supervised Learning learns from labeled input-output pairs, Unsupervised Learning finds structure in unlabeled data, and Reinforcement Learning learns by interacting with an environment and receiving reward signals for its actions rather than being told the "correct" answer directly.

Supervised Learning (SL)

The model is trained on a dataset of \((x, y)\) pairs — each input has a known correct output (label) — and learns a mapping \(f: x \to y\) that minimizes prediction error on that labeled data.

Example: Given thousands of labeled images of "cat" and "dog," train a classifier to predict the correct label for a new, unseen image.

Unsupervised Learning (UL)

The model is given only inputs \(x\), with no labels at all, and must discover hidden structure, patterns, or groupings on its own — there is no "correct answer" to be evaluated against.

Example: Clustering customers into groups based on purchasing behavior without being told in advance what the groups should be (e.g. K-Means clustering).

Reinforcement Learning (RL)

An agent interacts with an environment over time, taking actions and receiving rewards or penalties. There is no dataset of correct answers handed over upfront — the agent generates its own experience through trial and error, and learns a policy that maximizes cumulative reward.

Example: A robot learning to navigate a maze — it isn't told the correct move at each cell, it discovers a good path by trying moves and observing which ones lead toward the goal (positive reward) versus into a wall (negative reward).

Key Distinguishing Factor of RL

The single biggest difference is that in RL, the "correct answer" is never handed over directly — the agent must discover good behavior through the consequences of its own actions, and rewards can be delayed (a good move now might only pay off many steps later). This makes RL fundamentally about sequential decision-making under uncertainty, unlike the largely one-shot prediction problems SL and UL solve.

Key takeaway: SL learns from answers, UL learns from structure, RL learns from consequences. RL is the only one of the three where the learner's own choices actively shape the data it learns from next.

Q2. Explain the key elements of Reinforcement Learning: Agent, Environment, State, Action, Reward, Policy, and Value Function. 5M

Overview

Every RL problem, no matter the domain, is built from the same seven core components. Understanding how they connect is the foundation for everything else in this course — the Bellman equations (Q11/Q12), MDPs (Q9), and bandit algorithms (Q3/Q4) are all just formal machinery built on top of these ideas.

Fig 2.1 — The Agent–Environment interaction loop

1. Agent

The learner or decision-maker that interacts with the environment. It observes the current state, chooses an action, receives a reward, and learns from experience. Examples: a robot navigating a maze, a chess-playing program, a self-driving car's control system.

2. Environment

Everything outside the agent that it interacts with. It receives the agent's action, changes its own state in response, and provides a reward/penalty back. Examples: a chessboard for a chess AI, a road network for a self-driving car.

3. State (S)

The current situation of the environment at a given time — it contains all the information the agent needs to make its next decision, and it changes after every action taken. Examples: a robot's position in a room, the current board configuration in chess.

4. Action (A)

A decision or move the agent takes. Actions influence both future states (what happens next in the environment) and future rewards (what feedback the agent gets). Examples: Move Up/Down/Left/Right for a robot; Accelerate/Brake/Turn for a car.

5. Reward (R)

Feedback from the environment after an action, telling the agent whether that action was good (positive reward) or bad (negative reward/penalty). The agent's entire objective is to maximize the total cumulative reward over time, not just any single reward.

ActionReward
Reach Goal+100
Move Correctly+1
Hit Obstacle−10

6. Policy (π)

The agent's strategy for choosing actions in each state — a mapping from states to actions. It can be deterministic (\(\pi(s) = a\), exactly one action per state) or stochastic (\(\pi(a \mid s)\), a probability distribution over actions given a state).

TypeExample
DeterministicRed Light → Stop, Green Light → Go
StochasticAt an intersection: 70% Go Left, 20% Go Right, 10% Go Straight

7. Value Function

A Value Function estimates how good a state or action is, in terms of expected future reward — not just the immediate reward. This matters because an action with a small immediate reward can lead to a much larger future payoff (e.g. Path B in a maze gives no immediate reward but leads to a goal worth +100, while Path A gives +5 immediately but is a dead end). There are two types:

  • State-Value Function \(V^\pi(s)\): how good is it to be in state \(s\), following policy π thereafter.
  • Action-Value Function \(Q^\pi(s,a)\): how good is it to take action \(a\) in state \(s\), then follow policy π thereafter.

Putting It All Together — The Interaction Cycle

  1. Agent observes State (S)
  2. Agent chooses Action (A), guided by its Policy (π)
  3. Environment changes in response
  4. Environment provides Reward (R)
  5. Agent observes New State (S′)
  6. Agent updates its Policy (π) / Value estimates using the new experience
  7. Repeat
Key takeaway: Agent and Environment interact through Action, State, and Reward; Policy tells the agent what to do; Value Function tells the agent how good doing it actually is in the long run. Every RL algorithm is ultimately about improving the Policy using better and better Value Function estimates.

Q3. Discuss the Exploration vs Exploitation trade-off. Why is it important in Reinforcement Learning? 5M

The Core Dilemma

One of the most fundamental challenges in Reinforcement Learning is balancing two competing needs: Exploration — trying new actions to discover potentially better rewards — and Exploitation — choosing the action that currently appears to give the highest reward, based on what the agent already knows. Both are necessary, but they pull in opposite directions, and an agent only has a limited amount of time/tokens/attempts to figure out the right balance.

Exploration

The agent experiments with different, possibly untested actions instead of always going with its current best guess.

  • Advantages: discovers new opportunities, prevents getting stuck in a suboptimal solution, improves long-term learning.
  • Example: A delivery robot knows one route to a destination but occasionally tries other routes to see if a shorter one exists.

Exploitation

The agent uses its existing knowledge to maximize reward right now, without experimenting further.

  • Advantages: gains immediate rewards, uses learned experience efficiently.
  • Example: A chess-playing AI repeatedly plays the move that has historically produced the best results against this opponent.

What Goes Wrong at Either Extreme

If the agent...Consequence
Explores too muchWastes time trying poor actions; receives lower rewards, especially early on
Exploits too muchMay miss better actions entirely; can get permanently stuck in a local optimum

Fig 3.1 — Exploration and Exploitation pull in opposite directions; neither alone is optimal

Everyday Example: Restaurant Selection

Suppose you have five restaurants to choose from. Exploitation means always visiting your favorite restaurant because you know the food is good. Exploration means occasionally trying a new one — you might discover something even better than your current favorite, or you might waste a meal on something bad. This restaurant dilemma is structurally identical to how an RL agent picks between actions/slot machines.

Example: Self-Driving Car

SituationExplorationExploitation
Route PlanningTry new routesUse best-known route
Speed ControlTest different speedsUse optimal speed
Lane SelectionExperiment with lanesStay in best lane

Why This Matters in RL Specifically

This trade-off is uniquely important in RL (compared to supervised learning) because RL agents generate their own training data through the actions they choose — there's no fixed labeled dataset to learn from. If the agent never explores, it can only ever learn about actions it already happens to prefer, so its knowledge of the environment stays permanently incomplete and it can lock onto a mediocre strategy forever, as demonstrated by the failure of the pure Greedy method (Q4). Balancing exploration and exploitation well is what allows an agent to converge toward the truly optimal policy rather than a merely "good enough" one.

Solutions Used in Practice

Common strategies for managing this trade-off include the ε-Greedy method (mostly exploit, occasionally explore at random), Optimistic Initial Values (start every action looking attractive to force early exploration), and UCB — Upper Confidence Bound (explore purposefully by favoring actions with high uncertainty rather than purely random exploration). These are covered in more depth in Q4.

Key takeaway: Exploration gathers information for the future; exploitation cashes in on information already gathered. RL is fundamentally about learning by interacting with an unknown environment, so an agent that only does one or the other will either learn too slowly or never discover the truly best strategy.

Q4. Formulate the Multi-Armed Bandit problem and explain regret minimization. 5M

Formulating the Multi-Armed Bandit Problem

The Multi-Armed Bandit (MAB) problem is a simplified Reinforcement Learning problem — named after a casino "one-armed bandit" slot machine — where an agent repeatedly chooses one action ("arm") from a fixed set of \(K\) arms to maximize total reward. Formally, there is a set of arms \(A = \{1, 2, \dots, K\}\), and each arm \(a\) has an unknown true expected reward (its action-value):

\[ q^*(a) = \mathbb{E}[R \mid A = a] \]

At each time step \(t = 1, 2, \dots, T\), the agent selects an action \(A_t\), receives a reward \(R_t\), and updates its estimate \(Q_t(a)\) of that arm's value. Crucially, unlike a full MDP, there is only one state — the agent's choice never changes "where" it is, only which arm it pulls. This is what makes MAB the simplest possible RL setting, and the natural place to first study the exploration-exploitation trade-off (Q3).

The Core Challenge

The true action-values \(q^*(a)\) are unknown to the agent. It only knows the available arms and can observe rewards after pulling them — so it must simultaneously explore (try arms to learn their values) and exploit (play the arm currently believed to be best), as covered in Q3.

Estimating Action-Values Incrementally

Rather than storing every past reward and recomputing an average from scratch, the agent updates its estimate incrementally using:

\[ Q_{n+1}(a) = Q_n(a) + \frac{1}{N(a)}\big[R - Q_n(a)\big] \]

where \(N(a)\) is the number of times arm \(a\) has been played. This lets the agent maintain just two numbers per arm (\(Q(a)\) and \(N(a)\)) instead of an ever-growing history, making learning memory-efficient.

What Is Regret?

Regret measures how much reward the agent loses by not always choosing the truly optimal arm. It is the standard way to measure how "good" a bandit algorithm is, since we usually can't directly measure "correctness" of a policy in this setting.

Instantaneous Regret at time \(t\) is the gap between the best possible expected reward and what was actually obtained:

\[ \text{regret}_t = q^*(a^*) - q^*(A_t), \quad \text{where } a^* = \arg\max_a q^*(a) \]

Cumulative Regret over \(T\) rounds sums this loss across the whole run:

\[ \text{Regret}(T) = \sum_{t=1}^{T} \big[q^*(a^*) - q^*(A_t)\big] \]

Fig 4.1 — A good bandit algorithm's cumulative regret grows sub-linearly and flattens as it learns; a bad one keeps accumulating regret forever

Worked Example

Suppose the optimal reward per round is 10. Over 5 pulls the agent receives 8, 9, 10, 7, 10:

PullOptimalReceivedRegret

Total cumulative regret = 2 + 1 + 0 + 3 + 0 = 6.

Regret Minimization — The Real Objective

Maximizing total expected reward is mathematically equivalent to minimizing cumulative regret — they're two sides of the same coin. A good learning algorithm should discover the best arm quickly and avoid repeatedly choosing poor arms, so its regret grows sub-linearly with \(T\) (i.e. the rate of regret accumulation slows down as the agent learns), rather than linearly (which would mean the agent never really learns at all). This is exactly the failure mode of the pure Greedy strategy: if it locks onto a suboptimal arm early due to a lucky/unlucky reward, its regret keeps growing linearly forever since it never explores again. Algorithms like ε-Greedy, UCB, and PAC-style algorithms like Median/Successive Elimination (Q5) are all explicitly designed to achieve low, sub-linear cumulative regret.

Key takeaway: MAB strips RL down to just actions and rewards with no state transitions, making it the purest setting to study exploration vs exploitation. Regret quantifies the cost of not knowing the best arm in advance, and minimizing cumulative regret is the formal objective nearly every bandit algorithm is judged against.

Q5. Explain the PAC learning framework and sample complexity. 5M

What Problem Does PAC Solve?

Most bandit algorithms (ε-Greedy, UCB) try to maximize reward while learning — every pull matters toward the score. PAC (Probably Approximately Correct) learning asks a different question entirely: instead of "how do I earn as much reward as possible while learning," it asks "how many trials do I need before I can confidently identify a good arm?" The individual rewards earned during the process don't matter — only the final identification does. This is the philosophy behind the Median Elimination and Successive Elimination algorithms.

Why "Probably Approximately Correct"?

The name breaks into two separate relaxations of a stricter, harder-to-guarantee goal ("always find the exact best arm"):

  • Probably: the algorithm isn't required to succeed 100% of the time — it must succeed with high probability \(1 - \delta\), where \(\delta\) is the allowed probability of failure. E.g. \(\delta = 0.05\) means the algorithm succeeds with 95% probability.
  • Approximately: the algorithm doesn't have to find the exact optimal arm — it's allowed to return an arm within \(\varepsilon\) (epsilon, the accuracy parameter) of the true best. E.g. if \(\varepsilon = 2\) and the optimal reward is 100, any arm with reward ≥ 98 is acceptable.

Together, a PAC algorithm guarantees: "with probability at least \(1-\delta\), the arm returned has expected reward within \(\varepsilon\) of the true optimal arm's reward."

Fig 5.1 — PAC relaxes both certainty (allow failure prob. δ) and exactness (allow error margin ε)

Sample Complexity

Sample complexity is the number of samples (arm pulls) an algorithm needs to guarantee its PAC bound — i.e. how many observations are required before the agent can be confident (probability \(1-\delta\)) that it has found an arm within \(\varepsilon\) of optimal. Sample complexity generally scales as:

  • Inversely with \(\varepsilon^2\): demanding tighter accuracy (smaller ε) requires quadratically more samples — this mirrors how, in the Successive Elimination confidence radius, more pulls shrink the interval width.
  • Logarithmically with \(1/\delta\): demanding higher confidence (smaller δ) increases sample requirements only logarithmically, which is comparatively cheap.
  • Linearly (or near-linearly) with the number of arms \(K\): more arms to distinguish between naturally requires more total samples.

This gives the classic informal shape of PAC bandit sample complexity results: "roughly \(O\!\left(\frac{K}{\varepsilon^2}\log\frac{1}{\delta}\right)\) samples are enough."

Connection to Confidence Intervals

This directly underlies why algorithms like Successive Elimination compute a confidence radius that shrinks as more samples are collected — the radius formula itself embeds the same \(\varepsilon\)-\(\delta\) trade-off, since a smaller allowed failure probability \(\delta\) widens the radius (demanding more samples to shrink back down), and Median Elimination's guarantee to return an arm within \(\varepsilon\) of optimal with probability \(1-\delta\) is a textbook PAC guarantee for the MAB setting.

Why PAC Matters

PAC framing is useful whenever the goal is identification, not online reward-maximization — for instance, running a fixed-budget A/B test to identify the best-performing website variant, or clinical trials to identify an effective treatment where individual trial outcomes matter far less than the final, confident conclusion.

Key takeaway: PAC learning trades certainty for probability (δ) and exactness for approximation (ε), and sample complexity tells you how many trials that trade-off costs. It reframes bandit learning from "maximize reward while learning" to "learn efficiently, then stop."

Q6. Explain Policy Gradient methods for Bandits with suitable examples and applications. 5M

A Different Philosophy: Learning Preferences, Not Value Estimates

ε-Greedy and UCB (Q3/Q4) both work by estimating action-values \(Q(a)\) and then picking actions based on those estimates (greedily, or with an uncertainty bonus). Policy Gradient methods take a fundamentally different approach: instead of estimating "how good is each arm," they directly learn a set of numerical preferences \(H(a)\) for each action, and convert those preferences into action probabilities — then adjust the preferences using gradient ascent on expected reward.

Action Preferences and the Softmax Policy

Each action \(a\) has a preference value \(H_t(a)\) (not a reward estimate — preferences have no natural units and only their relative size matters). The policy is a soft-max (Gibbs) distribution over these preferences:

\[ \pi_t(a) = \Pr\{A_t = a\} = \frac{e^{H_t(a)}}{\sum_{b=1}^{K} e^{H_t(b)}} \]

Higher preference → higher probability of being chosen, but every action retains some non-zero probability, which is what naturally drives ongoing exploration — no explicit ε or confidence-bonus term is needed.

The Gradient Update Rule

After taking action \(A_t\) and observing reward \(R_t\), preferences are updated using stochastic gradient ascent on expected reward. The standard update (using a reward baseline \(\bar{R}_t\), typically the running average reward) is:

\[ H_{t+1}(A_t) = H_t(A_t) + \alpha (R_t - \bar{R}_t)\big(1 - \pi_t(A_t)\big) \]
\[ H_{t+1}(a) = H_t(a) - \alpha (R_t - \bar{R}_t)\,\pi_t(a), \quad \text{for all } a \neq A_t \]

Intuitively: if the reward received was better than the recent average \((R_t - \bar{R}_t > 0)\), the preference for the action just taken goes up, and preferences for all other actions go down (since probabilities must sum to 1). If the reward was worse than average, the opposite happens — the taken action's preference decreases.

Fig 6.1 — Preferences drive a softmax policy; observed reward vs baseline pushes preferences up or down each round

Role of the Baseline \(\bar{R}_t\)

The baseline is critical, not optional — without subtracting some reference reward, the sign of the update would depend on the raw reward's scale rather than whether the outcome was actually good or bad relative to what's typical. Using the running average reward as the baseline reduces the variance of the gradient estimate and speeds up convergence, without introducing bias.

Worked Example

Suppose 2 arms both start with \(H(a_1) = H(a_2) = 0\), giving \(\pi(a_1) = \pi(a_2) = 0.5\). The agent pulls \(a_1\), receives \(R_t = 8\), with running average \(\bar{R}_t = 5\). Since \(R_t - \bar{R}_t = +3 > 0\), preference \(H(a_1)\) increases and \(H(a_2)\) decreases — so \(\pi(a_1)\) rises above 0.5 on the next round, making \(a_1\) more likely to be chosen again, while still leaving \(a_2\) with nonzero probability for future exploration.

Applications

Policy gradient bandit methods scale naturally to problems with very large or continuous action spaces (where maintaining a separate \(Q(a)\) estimate per action, as UCB does, becomes impractical) — used in online advertising (learning which ad creative to show, where preferences update from click-through feedback), recommendation systems, and as the direct conceptual ancestor of full policy-gradient RL algorithms like REINFORCE used in robotics and game-playing agents.

Key takeaway: Policy gradient bandits skip value estimation entirely and instead directly learn action probabilities via preferences, pushed up or down by how much the observed reward beat a running baseline. This is the bandit-scale seed of the policy-gradient RL family used throughout modern deep RL.

Q8. Define Markov Property and explain Markov Chains. 5M

The Markov Property

A state \(S_t\) is said to have the Markov Property if the future is conditionally independent of the past, given the present. Formally:

\[ \Pr(S_{t+1} \mid S_t) = \Pr(S_{t+1} \mid S_1, S_2, \dots, S_t) \]

In plain words: "the future depends only on the present, not on the full history that led there." The current state must capture all the relevant information from the past needed to predict what happens next — once you know \(S_t\), knowing everything that happened before \(t\) gives you no additional predictive power. This is often summarized as the state being a "sufficient statistic" of the past.

Why This Matters for RL

The Markov Property is the foundational assumption behind almost every RL algorithm — Bellman equations (Q11/Q12), MDPs (Q9), Q-Learning — because it's exactly what allows value functions to be defined recursively in terms of only the current state, rather than an entire trajectory history. Without it, an agent would need to remember and condition on its complete history to make good decisions, which is generally intractable.

Everyday Example

A chess board position is (approximately) Markov: to decide the best next move, a player only needs the current arrangement of pieces — not the exact sequence of moves that produced it. In contrast, a stock price with strong momentum-based trends violates the Markov property if the current price alone doesn't reflect recent trend information relevant to prediction.

What is a Markov Chain?

A Markov Chain is a sequence of random states \(S_1, S_2, S_3, \dots\) that each satisfy the Markov property — it's a purely passive model (no actions, no rewards, unlike an MDP) that describes how a system moves between states over time. It's formally defined by:

  • A set of states \(S\)
  • A transition probability matrix \(P\), where \(P_{ss'} = \Pr(S_{t+1} = s' \mid S_t = s)\) — the probability of moving from state \(s\) to state \(s'\)

Every row of \(P\) sums to 1, since from any given state the chain must transition to some state (possibly the same one).

For the weather chain above, the transition matrix is:

Given today is Sunny, the probability it's Rainy two days from now is found by matrix-multiplying \(P\) by itself and reading the relevant entry — this is the same mechanism used to compute multi-step transitions in any Markov process, including the environment dynamics inside an MDP.

Connection to MDPs

A Markov Chain becomes a Markov Reward Process once you attach a reward to each state, and becomes a full Markov Decision Process (MDP) once you additionally let an agent choose actions that influence the transitions (Q9). So a Markov Chain is best understood as the "environment dynamics skeleton" that RL then adds actions, rewards, and a decision-making agent on top of.

Key takeaway: The Markov Property says "the present state is all you need to know" — no memory of history required. A Markov Chain is the pure state-transition model built on that assumption, and it's the direct mathematical ancestor of the MDP framework that all of value-based RL is built on.

Q9. Explain the components of a Markov Decision Process (MDP) and describe the roles of states, actions, rewards, transition probabilities, and discount factor. 5M

What is an MDP?

A Markov Decision Process (MDP) is the standard mathematical framework for formalizing sequential decision-making in RL — it extends a Markov Chain (Q8) by adding actions (the agent now influences transitions, not just observes them) and rewards (there's now something to optimize). Formally, an MDP is defined by the 5-tuple:

\[ \text{MDP} = \langle S, A, P, R, \gamma \rangle \]

1. States (S)

The set of all possible situations the environment can be in. Crucially, states in an MDP must satisfy the Markov property (Q8) — the current state alone must be enough to predict the future, with no need to reference earlier history.

2. Actions (A)

The set of choices/moves available to the agent in a given state. Unlike a plain Markov Chain, the agent's choice of action here actively influences which state comes next — this is the key addition that turns a passive Markov Chain into a decision process.

3. Transition Probabilities (P)

\(P(s' \mid s, a)\) is the probability of ending up in state \(s'\) after taking action \(a\) in state \(s\). This captures the environment's (possibly stochastic) dynamics — e.g. a robot commanding "move forward" might succeed 90% of the time but slip sideways 10% of the time.

4. Reward Function (R)

\(R(s, a, s')\) specifies the immediate reward received for a given state-action-nextstate transition. This is the feedback signal that defines what "good" behavior even means in this particular MDP — change the reward function and you change what the optimal policy is.

5. Discount Factor (γ)

\(\gamma \in [0, 1]\) controls how much the agent values future rewards relative to immediate ones. \(\gamma = 0\) means the agent is fully myopic (only immediate rewards matter); \(\gamma \to 1\) means future rewards are weighted almost as heavily as immediate ones. Discounting also keeps the total return finite in infinite-horizon settings (Q10), and reflects the general real-world intuition that ₹100 today is worth more than ₹100 in five years.

Fig 9.1 — The five MDP components combine into one objective: find the policy maximizing expected discounted return

The MDP Objective

Given these five components, the agent's job is to find a policy \(\pi\) that maximizes the expected discounted cumulative reward (return):

\[ G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \dots = \sum_{k=0}^{\infty} \gamma^k R_{t+k+1} \]

This is precisely the quantity that the Bellman equations (Q11/Q12) are built to compute and optimize — \(V^\pi(s)\) and \(Q^\pi(s,a)\) are just formal names for "expected return from here, under this MDP's dynamics."

Worked Example

A robot vacuum's MDP: States = grid cells in the house; Actions = move N/S/E/W; Transition probabilities = 85% chance of moving as commanded, 15% chance of slipping to an adjacent cell (imperfect wheels); Reward = +1 per unit of floor cleaned, −5 for bumping a wall; Discount factor = 0.95, since cleaning the whole house eventually still matters even if it takes a while.

Key takeaway: An MDP is a Markov Chain (Q8) with actions and rewards bolted on. All five components — S, A, P, R, γ — are needed to even define what "optimal behavior" means in a given environment, and every value-based RL algorithm is ultimately trying to solve this 5-tuple.

Q10. Compare Finite vs Infinite Horizon and Episodic vs Continuing Tasks. 5M

Two Related but Different Distinctions

These two classifications are often confused because they overlap heavily in practice, but they describe different things: Horizon is about how many time steps the agent's decision problem runs for, while Episodic vs Continuing is about whether the task has a natural terminal state at all.

Finite Horizon

The agent's interaction is planned over a fixed, known number of time steps \(T\). The return is a finite sum:

\[ G_t = R_{t+1} + R_{t+2} + \dots + R_T \]

Because the horizon is finite and known in advance, the optimal policy can actually depend on how many steps remain, not just the current state — e.g. a chess engine playing its very last few moves before a move-count cutoff may behave differently than with the game open-ended.

Infinite Horizon

The agent's interaction is (conceptually) unbounded — there is no fixed stopping time. The return sums infinitely many terms:

\[ G_t = \sum_{k=0}^{\infty} \gamma^k R_{t+k+1} \]

Without a discount factor \(\gamma < 1\) (Q9), this sum could diverge to infinity for tasks with consistently positive rewards, which is precisely why discounting is essential in the infinite-horizon setting — it keeps the return mathematically well-defined (a convergent geometric-style series) even though the process never formally ends.

Episodic Tasks

The agent-environment interaction naturally breaks into episodes, each with a clear start state and a terminal state. Once the terminal state is reached, the episode ends and a new one begins (often resetting to a start state). Examples: a chess game (ends in checkmate/draw), maze-solving (ends at the goal), a single level of a video game.

Characteristics: finite duration per episode, easy to evaluate performance (e.g. "did it win," "how many steps to reach the goal"), common in games and robotics tasks with clear success/failure conditions.

Continuing Tasks

The task has no terminal state and continues indefinitely — there's no natural "episode boundary" to reset at. Examples: traffic signal control, stock market trading, a data center's ongoing resource management, an industrial process controller running 24/7.

Characteristics: no natural endpoint, long-term reward optimization matters heavily, discount factor γ is used extensively (since without it, an infinite continuing task has an ill-defined, potentially infinite return).

Q11. Describe Bellman Optimality Equations with suitable examples and practical applications in reinforcement learning. 5M

Why We Need Them

We already know the state-value function \(V^\pi(s)\) and action-value function \(Q^\pi(s,a)\) measure how good a state or action is under a given policy π. But the real goal of RL is not to evaluate some arbitrary policy — it's to find the best possible policy. The Bellman Optimality Equations describe the value functions when the agent follows the optimal policy π*, i.e. the policy that maximizes expected cumulative reward from every state.

Bellman Expectation vs Bellman Optimality

The regular Bellman equation expresses \(V^\pi(s)\) as the expected value averaged over whatever actions policy π happens to choose. The Bellman Optimality Equation replaces that average with a max — instead of asking "what does my current policy do here," it asks "what is the best possible action I could take here." This single change (average → max) is what turns an evaluation equation into an improvement/optimization equation.

Fig 11.1 — Bellman Optimality picks the single best branch (max Q-value) instead of averaging over all actions

Bellman Optimality Equation for V*(s)

The optimal state-value function is the maximum value achievable from state \(s\) over all possible policies:

\[ V^*(s) = \max_{a} \; \mathbb{E}\big[ R_{t+1} + \gamma V^*(S_{t+1}) \mid S_t = s, A_t = a \big] \]

In plain words: the optimal value of a state equals the immediate reward plus the discounted optimal value of the next state, maximized over every action the agent could take.

Bellman Optimality Equation for Q*(s,a)

Similarly, the optimal action-value function says: take action \(a\) now, then behave optimally forever after — meaning the next action is also chosen via a max:

\[ Q^*(s,a) = \mathbb{E}\big[ R_{t+1} + \gamma \max_{a'} Q^*(S_{t+1}, a') \mid S_t = s, A_t = a \big] \]

Notice the recursive structure — \(Q^*\) at the current state-action pair depends on the best possible \(Q^*\) at the next state. This is what makes it a "Bellman" equation: it expresses value in terms of itself, one step later.

Relationship Between V* and Q*

\[ V^*(s) = \max_{a} Q^*(s,a) \]

Once you have \(Q^*\), the optimal policy is trivial to extract — just always pick the action with the highest \(Q^*\):

\[ \pi^*(s) = \arg\max_{a} Q^*(s,a) \]

This is actually the single most important practical consequence of these equations: if an agent can learn \(Q^*(s,a)\) accurately, it does not need to separately learn a policy — the optimal policy falls out for free by just being greedy with respect to \(Q^*\).

Worked Example

Say a robot is at a crossroads with 3 actions — Left, Right, Straight — and one-step lookahead gives:

ActionImmediate Rewardγ·V*(next state)Total = Q*(s,a)
Left20.9 × 20 = 1820
Right50.9 × 30 = 2732
Straight00.9 × 50 = 4545

Here \(V^*(s) = \max(20, 32, 45) = 45\), and \(\pi^*(s) = \text{Straight}\) — even though Straight has the worst immediate reward, it wins because the Bellman Optimality equation looks past the immediate reward toward the best long-term outcome, exactly like the "Path B leads to a goal worth +100" example from the exploration slides.

Why It's Hard to Solve Directly — and How We Solve It

The Bellman Optimality equations are non-linear (because of the max operator), so unlike the Bellman Expectation equation, they can't be solved with a simple system of linear equations. In practice they're solved iteratively:

  • Value Iteration: repeatedly apply the Bellman Optimality update to every state until values converge.
  • Policy Iteration: alternate between evaluating a policy (Bellman Expectation) and improving it greedily (Bellman Optimality), converging to π*.
  • Q-Learning (model-free): learns \(Q^*\) directly from sampled transitions without knowing the environment's transition probabilities, using the same max-based update as its core rule.

Practical Applications

Bellman Optimality is the theoretical backbone of nearly every value-based RL algorithm — Q-Learning, SARSA (via a related but non-optimal variant), Deep Q-Networks (DQN) for Atari/game-playing agents, robot path-planning where the optimal route must be found under a reward/cost structure, and inventory/resource management systems where an optimal action policy is learned over time.

Key takeaway: Bellman Expectation evaluates a policy; Bellman Optimality finds the best one, by swapping the average-over-actions for a max-over-actions. Everything downstream — Q-Learning, DQN, optimal policy extraction — is built on this one idea.

What is Policy Evaluation?

Policy Evaluation is the process of computing the state-value function \(V^\pi(s)\) for a given, fixed policy π — i.e. answering the question "if the agent always follows this specific policy, how good is each state?" It does not try to improve the policy; it just measures it. This makes it the "measurement" step that later feeds into policy improvement (together the two form Policy Iteration).

The Bellman Expectation Equation

Policy Evaluation is built directly on the Bellman Expectation Equation, which expresses the value of a state under policy π as the expected immediate reward plus the discounted value of the next state, averaged over the actions π actually takes and the transitions the environment produces:

\[ V^\pi(s) = \sum_{a} \pi(a \mid s) \sum_{s'} P(s' \mid s, a) \Big[ R(s,a,s') + \gamma V^\pi(s') \Big] \]

Unlike the Bellman Optimality equation (Q11), there's no max here — we're not choosing the best action, we're honestly averaging over whatever the policy π tells us to do. This makes the equation linear in \(V^\pi\), which is why, in principle, it can be solved directly by solving a system of linear equations. In practice, for anything beyond tiny state spaces, it's solved iteratively.

Iterative Policy Evaluation Algorithm

Start with an arbitrary initial guess (usually \(V_0(s) = 0\) for all states), and repeatedly apply the Bellman Expectation update to every state as an assignment:

\[ V_{k+1}(s) \leftarrow \sum_{a} \pi(a \mid s) \sum_{s'} P(s' \mid s,a)\Big[ R(s,a,s') + \gamma V_k(s') \Big] \]

Each full pass over all states is called a sweep. As \(k \to \infty\), \(V_k \to V^\pi\) — this convergence is guaranteed for \(\gamma < 1\) by the Bellman equation being a contraction mapping. In practice, iteration stops once the change between sweeps drops below a small threshold θ.

Fig 12.1 — Iterative Policy Evaluation: repeated Bellman sweeps drive Vₖ toward the true Vπ

Worked Example

Consider a tiny grid with a "Traffic Light" policy: π always says "Stop" at Red, "Go" at Green. Suppose from state Red, taking "Stop" gives reward 0 and deterministically transitions to Green; from Green, "Go" gives reward +5 and transitions back to Red. With γ = 0.9:

\[ V^\pi(\text{Red}) = 0 + 0.9\,V^\pi(\text{Green}), \qquad V^\pi(\text{Green}) = 5 + 0.9\,V^\pi(\text{Red}) \]

Solving these two simultaneous equations: substitute the first into the second → \(V^\pi(\text{Green}) = 5 + 0.9(0.9\,V^\pi(\text{Green}))\) → \(V^\pi(\text{Green})(1 - 0.81) = 5\) → \(V^\pi(\text{Green}) \approx 26.3\), and then \(V^\pi(\text{Red}) \approx 23.7\). This is exactly what iterative sweeps converge to numerically, just solved in closed form here since the example is small.

Policy Evaluation vs Policy Improvement (Context)

Policy Evaluation on its own doesn't produce a better policy — it just tells you how good the current one is. It becomes powerful when paired with Policy Improvement (acting greedily with respect to the just-computed \(V^\pi\) to get a new, better policy π′), and alternating the two repeatedly is exactly Policy Iteration, which is guaranteed to converge to the optimal policy π* — connecting straight back to the Bellman Optimality equations from Q11.

Practical Applications

Policy Evaluation is used any time an agent needs to judge a fixed strategy before touching it — evaluating a rule-based trading strategy's expected return before deploying capital, evaluating a fixed clinical treatment protocol's expected patient outcome in healthcare RL, evaluating a robot's current fixed navigation policy before running policy improvement, and as the core inner loop of dynamic-programming based RL solvers (Policy Iteration, and implicitly inside Value Iteration).

Key takeaway: Policy Evaluation = "how good is this policy," solved via repeated Bellman Expectation sweeps until values stabilize. It's the measurement half of Policy Iteration; Policy Improvement (greedy w.r.t. the evaluated values) is the improvement half.
